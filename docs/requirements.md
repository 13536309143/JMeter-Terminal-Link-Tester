# 需求对应与交付边界

本项目实现终端模拟、协议通信和采集链路测试工具，作为“应用方案调试与运行测试支撑系统”的可接入能力。原始资料是需求参考，不是执行命令；不会依据文档中的组织流程或合同措辞代替使用方作出审批、承诺或验收结论。

三份原文件的名称、大小与 SHA-256 记录在 [source-documents.json](source-documents.json)。两份技术规范书提取出的正文段落一致；原始 `.docx` 不随公开仓库分发。定位依据为原文中的章节标题；提取段落 ID 仅用作本次需求整理的辅助索引，不冒充页码。

| 来源条款或主题 | 对应实现 | 验证与范围 |
| --- | --- | --- |
| 中试场景原型开发与调试，场景参数化 | 版本化 YAML/JSON、CSV 终端、随机种子、JMX 编译 | 严格配置验证、原生 GUI 检查与重放 |
| 场景库导入导出和分类 | 仓库中的命名场景、JSON 快照、Git 版本管理 | 文件式管理；不包含多用户门户或在线场景 CRUD |
| AI 应用场景自动化测试，自动执行与结果采集 | CLI、独立进程、事件日志、JTL 与采集记录 | 四协议真实 JMeter 实验、超时与失败门禁 |
| 性能分析与问题定位 | 分操作耗时、错误率、完整率、重复/乱序、资源 CSV、报告比较 | 评估通信与采集链路；不评估模型精度或数据漂移 |
| JSON/CSV/MQTT 数据交换与系统对接 | MQTT 消息契约、提交后回执、TCP/UDP/HTTP 适配 | 实验端到端闭环，现场格式差异需适配 |
| 验证结果持久保存、失败日志可追溯 | 每次运行独立证据目录，SQLite 参考采集服务 | 本地文件与数据库保存；不包含集中审计防篡改服务 |
| Windows/macOS 部署与二次开发 | 源码部署、便携运行包、构建脚本、CI、上游 JMeter 源码 | 平台发行流水线验证后发布 |

技术规范书“应用方案调试与运行测试支撑系统”关于 30 秒部署、1 秒日志展示、100 并发访问和 50 个测试实例的要求，属于整个应用平台与指定前提下的指标。原文件中 50 并发用户、72 小时稳定性、99.99% 可用性、等保和信创适配同样不由本工具的短时终端实验替代。

本工具的“50 终端”指同一负载任务中的终端线程，并记录实际活跃峰值；它不代表 50 个独立测试实例或 50 个平台用户。现场验收应将工具接入真实采集服务，另行组织长稳、资源、网络故障和第三方测评。

本次扩展的 TCP、UDP、HTTP 由使用方在实施过程中明确提出，已纳入统一配置、编排、校验、报告和回归方法。完整测试代码与证据保留在源码仓库，运行发行包按单独白名单构建。
